# 微信读书打卡（dsh-weread-checkin）

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)
![DSH](https://img.shields.io/badge/DeepSeek%20Harness-plugin-blue)

在 [DeepSeek Harness](https://github.com/deepseek-ai) 里完成微信读书每日打卡：手动一键、每天定时、或让 AI 代劳。

当前版本 **v1.1.8**（版本号会自动显示在插件面板底部与设置页「关于」里）。

> **只需要一次 Cookie，不需要抓包。** 上报模板有内置兜底，粘一次 Cookie 就能用。

## 安装

### 第一步：装好 DSH 桌面端

本插件是 DSH 的 bundle，**不能单独运行**，先确认桌面端能正常打开。
插件只要求 `node >= 20`，DSH 自带 runtime，不用另外装 Node。

### 第二步：把源码放到本机

插件代码在 GitHub 上，DSH 只能装**本机目录**，所以先要在磁盘上有一份完整的源码。
下面两种做法**选一种就行**，区别只在于以后能不能一键 `git pull` 更新。

#### 做法 A：下载 zip（不用装任何东西，推荐新手）

1. 在浏览器地址栏粘贴这一行，回车：

   ```
   https://codeload.github.com/zhangyxx1996/dsh-weread-checkin/zip/refs/tags/v1.1.8
   ```

   它会**直接开始下载**一个约 80 KB 的文件 `dsh-weread-checkin-1.1.8.zip`（不会跳转到别的页面）。

2. 打开「下载」文件夹，右键这个 zip → **全部解压缩**（Windows 自带，不用装 WinRAR / 7-Zip）。

3. 解压出来是一个名为 `dsh-weread-checkin-1.1.8` 的文件夹，里面应该能直接看到
   `package.json`、`index.js`、`client.js` 这几个文件。
   **如果打开后里面还套着一层同名文件夹，说明多套了一层，把里面那层拿出来用。**

4. 把这个文件夹挪到你想长期放的地方，比如 `D:\DSH工作区\`，并**改成好记的名字**：

   ```
   D:\DSH工作区\微信读书插件\
   ```

   路径里有中文和空格都没问题。**关键是记住这个绝对路径**，第三步要用。

> 缺点：zip 是某个版本的定版快照，没有 git 历史。以后想看改了什么、或者想回滚，
> 只能重新下另一个版本的 zip。
>
> 想拿**当前最新代码**而不是定版，把上面链接里的 `tags/v1.1.8` 换成 `heads/main` 即可：
> `https://codeload.github.com/zhangyxx1996/dsh-weread-checkin/zip/refs/heads/main`
> （下载的文件名会变成 `dsh-weread-checkin-main.zip`）。想更新时重新下一遍、解压覆盖原目录即可。

#### 做法 B：用 git clone（能持续更新）

先确认装没装 git —— 打开 PowerShell 输入 `git --version`，能打印版本号才继续。
**报「无法将 git 项识别为 cmdlet」就是没装**，去 https://git-scm.com/download/win 装一个（一路下一步即可），
装完**关掉所有终端和 DSH 重开**，PATH 才会生效。

然后：

```powershell
# 1. 先建好父目录（不存在的话）
New-Item -ItemType Directory -Path 'D:\DSH工作区' -Force

# 2. 克隆。最后一个参数就是你想要的本地目录，不存在会自动创建
git clone https://github.com/zhangyxx1996/dsh-weread-checkin.git 'D:\DSH工作区\微信读书插件'

# 3. 确认拿到了
Get-ChildItem 'D:\DSH工作区\微信读书插件' -Filter package.json
```

看到 `package.json` 就成功了。以后想更新到最新版，在该目录里执行 `git pull` 即可。

> 本仓库是**公开**的，`clone` 不需要账号或 token。以后要往仓库推送才需要凭据，
> 用 `git config --global credential.helper manager` 存一次即可，
> **不要**把 token 拼进 URL（那会以明文留在 `.git/config` 里）。

### 第三步：装进 DSH

打开 DSH，把这段交给 AI：

> 把 `D:\DSH工作区\微信读书插件` 这个本地目录作为 bundle 装进当前 profile，然后提示我重启 DSH。

等价于 `plugin_manager install_bundle`：它会在 profile 的 `package.json` 里加一条
`link:<绝对路径>` 依赖，并写进 `dsh.profile.bundles`。之后 `profiles/<profile>/node_modules/dsh-weread-checkin`
是一个指向源码目录的 **Junction（软链）**，不是副本。

> **改代码后必须重启 DSH** 才会加载新版本。软链方式下不需要重装，但需要重启。

### 第四步：配凭据（二选一）

**方式 A：界面里重填**（推荐换机器时用）

点左侧栏书本图标 → 右下角「设置」→ 粘贴 Cookie 与 API Key → 保存。

**方式 B：拷旧机器的文件**（保留每日目标、打卡时长、自动打卡时间）

```
%USERPROFILE%\.dsh\weread-credentials.json     # Cookie + 请求体模板 + API Key
%USERPROFILE%\.dsh\weread-state.json           # 自动打卡时间、时长档位、今日进度
```

这两个文件是**纯 JSON，没有做机器绑定加密**，可以直接拷。
插件读取时先看 `DSH_PROFILE_DIR`（`~\.dsh\profiles\desktop`），再回退 `DSH_HOME`（`~\.dsh`），
所以放在 `~\.dsh` 根下或 profile 目录下都能被识别；写入统一走 profile 目录。

> 换机器后注意：两台都开「自动打卡」不会冲突（打卡是补差额、达标即停），
> 但会各报一次时长。建议只在常用那台开。

装好后左侧栏会出现一个书本图标，带三色状态点。

## 迁移到另一台电脑

上面的四步就是完整流程，另外两点值得提前知道：

| 事项 | 说明 |
|---|---|
| 不需要 token | 仓库是公开的，`clone` / 下载 zip 都不用凭据。只有 `push` 要，用 `git config --global credential.helper manager` 单独存，**别把 token 写进 remote URL** |
| 发版脚本可移植 | `release.ps1` 会自动定位 git / node / pnpm（先 PATH，再翻 `~\.dsh\dsh-runtimes\*`），profile 目录读 `DSH_PROFILE_DIR`，换机器换目录不用改 |

想把**对话历史**也搬过去也可以：DSH 会话存在
`~\.dsh\sessions\<工作区目录名>\<会话 id>\session.v4.jsonl.zstd`，
目录名由工作区绝对路径生成（非 ASCII 字符 → `~` + 4 位大写十六进制码位，其余连续非字母数字折叠成一个 `-`，两端各加 `--`）。
新机器如果工作区路径和旧机完全一致，把会话目录连同 `~\.dsh\storages\session_projcache\sessions\<会话 id>.json` 一起拷过去即可；
路径不同则需按新路径重算目录名。**通常没必要搬**——版本的真相都在 git 里，新开一个会话读 README + `git log` 就能接上。

## 快速开始

1. 点左侧栏的书本图标 → 面板右下角「设置」
2. 浏览器打开 [weread.qq.com](https://weread.qq.com) 并确认已登录
3. `F12` → Network → 过滤 `read` → 随便翻一页书，出现 `/web/book/read` 请求
4. 右键那条请求 → Copy → **Copy as cURL (bash)**
5. 整段粘进插件设置页的 Cookie 框 → 保存

就这么两步。Cookie 保存在本机 `~/.dsh/weread-credentials.json`，不会写进插件配置、也不会传给任何第三方。

**wr_skey 约 90 分钟过期**，插件会自动续期；整体登录态约 30 天，届时重新粘一次即可。

## 原理

微信读书**没有独立的「打卡」接口**。服务端把「当日有效阅读时长 ≥ 5 分钟」自动记为一个打卡天，
所以本插件通过 `POST https://weread.qq.com/web/book/read` 每 30 秒上报一次阅读时长来实现打卡。
读书小队积分同样由阅读时长驱动，因此也会被一并累积。

> 接口与签名算法逐字对照 [findmover/wxread](https://github.com/findmover/wxread) 的
> `main.py` / `config.py` 实现，并用 6 组用例与 Python 源码逐例比对，结果完全一致。

## 两个概念，别混

| | 每日目标 | 打卡时长 |
|---|---|---|
| 作用 | 判定「今天算不算打卡成功」 | 一次点击最多补多少分钟 |
| 影响 | 进度条、日历颜色、侧边栏圆点 | 单次跑多久、自动打卡跑多久 |
| 档位 | 5 / 10 / 15 / 20 / 30 / 45 / 60 分钟 | 5 / 10 / 15 / 20 / 30 / 45 / 60 分钟 |

点「立即打卡」是**补差额**：今天已读 3 分钟、目标是 10 分钟，就只跑 7 分钟，凑满即停。
已经达标时按钮直接变成「今日已达标」，不会重复上报。

## 界面

**左侧栏的书本图标带一个三色状态点**，一眼看出今天的情况：

| 颜色 | 含义 |
|---|---|
| 绿 | 今日阅读已达「每日目标」 |
| 黄 | 今天还没打满（未达成目标） |
| 红 | Cookie 失效 / 未配置 / 最近一次运行报错 |

> 红点是真·登录态探测的结果：插件会实际请求一次 `/web/login/renewal`（带 `ql:true`）。
> 否则 Cookie 过期时官方 API Key 通道照样返回漂亮统计，就成了「假绿」。

点图标打开面板，iOS 风格的分组卡片依次是：

- **今日** —— 大号当前时长 / 目标、进度条（按每日目标推进，达成变绿）、一键「立即打卡」
  - 打卡进行中：按钮变灰显示 `打卡中 6/20`，带转圈，不可点击
  - 进度条实时前进：每 30 秒刷新一次，不用手动刷
- **打卡设置** —— 每日目标、打卡时长、自动打卡时间
- **打卡日历** —— 周 / 月可切换，**一周从周一开头**，两种视图都能往回翻看历史
  - 周视图：一周七格，带 ‹ › 翻周；翻到上一周会自动补拉历史数据
  - 月视图：月历，可翻到 2026 年 1 月为止的历史
  - 达标绿色（按超出目标的多少分 4 档深浅）、未达标红色（按完成度分 3 档）
  - 数据还没到时会显示「正在读取历史…」，**不会把未知画成「未读」红色**；
    拉取失败给出原因和「重试」按钮，且只请求一次（不会反复重试刷接口）
- **我的书架** —— 常驻显示两排封面（点「全部 N 本」展开全部）；每本书下方是今年阅读时长，按今年时长排序
- **累计** —— 总阅读时长、有效阅读天数、读过 / 读完 / 笔记数

**取数时机**（省流量也省接口）：

| 场景 | 行为 |
|---|---|
| 打开面板 | 拉一次最新数据（含书架，因为它常驻显示） |
| 打卡进行中 | 每 30 秒刷新一次进度 |
| 切到日历「月」视图 | 此时才请求 2026-01-01 起的历史 |
| 周视图往回翻到上一周 | 同样补拉一次历史（本周是自足的，不拉） |
| 再次打开面板 | 书架命中本地缓存，不重复请求 |
| 空闲 | 不轮询（只有侧边栏圆点每 2 分钟探一次登录态） |

## 配置

在界面里粘贴即可，**不用手动编辑任何文件，也不需要抓包**。
打开 **设置 → 插件 → 微信读书打卡**：

### ① Cookie（必需）

1. 浏览器打开 https://weread.qq.com/ 并确认已登录
2. F12 → Network → 过滤 `read` → 点 `https://weread.qq.com/web/book/read`
3. 右键 → **Copy → Copy as cURL (bash)**
4. 整段 cURL 粘进 Cookie 框 → 保存（只粘 Cookie 字符串也行，插件两种都能解析）

### ② 请求体模板（可选，留空即用内置模板）

上报接口的 `b`（书籍）、`c`（章节哈希）、`ps`/`pc`（用户与设备标识）理论上需要是同一次
真实阅读产生的配对。但实测服务端**不逐字段校验**——只要这组值曾经真实产生过就能通过：

```
内置模板 → 上报 → 官方统计今日 1197 → 1230 秒（+33，正好等于两次 rt 之和）
```

所以内置了一份实测可用的模板作为兜底，**普通用户完全不用抓包**。
只有当内置模板日后失效时，才需要按上面的步骤把 `/web/book/read` 的请求体粘进第二个框覆盖它。

### ③ 官方 API Key（可选，但强烈建议）

形如 `wrk-xxxxx`，从微信读书官方 skills 处获取。配上它之后才能**验证**打卡是否真的计入时长，
日历、书架、累计统计也都依赖它。

凭据保存在本机的 `C:\Users\<你>\.dsh\weread-credentials.json`，不写进插件配置。

> Windows 上如果把 Key 写在「用户环境变量」里，已经在运行的 Host 进程读不到
> （进程环境在启动时固定），所以请在设置页里也填一份。

## 验证打卡是否真的生效

**只看 `{"succ":1}` 是不够的**——请求被接受不等于时长已累加。插件的做法是：

```
打卡前读官方 /readdata/detail 的「今日」秒数
  → 执行上报
  → 再读一次，比对增量
```

面板打卡成功后直接显示「打卡生效：今日阅读 +N 秒」；没涨就明确报错，不会假装成功。

## 使用方式

| 方式 | 说明 |
|---|---|
| 左侧栏面板 | 点书本图标 → 「立即打卡」，实时显示时长是否增长 |
| 插件设置页 | 粘贴 Cookie / 模板 / API Key、刷新密钥 |
| `/weread` | 在输入框执行，`/weread 30` 可指定分钟数（会覆盖补差额逻辑） |
| 对话 | 对 AI 说「帮我微信读书打卡」（工具 `weread_checkin`） |
| 自动 | 面板里设时间（如 `08:30`），每天该时刻自动跑一次 |

五者共用同一份实现。自动打卡由插件内置定时器驱动，**不会出现在「自动化任务」界面，
也不消耗对话 token**，代价是那一刻 DSH 需要在运行。

> 定时器有补跑语义：到点后如果 DSH 没开，下次启动后仍会补上（一天最多补 3 次）。

## 配置项（`cordis.patch.yml`）

| 字段 | 默认 | 说明 |
|---|---|---|
| `minutes` | `10` | 默认打卡时长（分钟）；面板里改过就以面板为准 |
| `goalMinutes` | `10` | 默认每日目标；面板里改过就以面板为准 |
| `autoTime` | `""` | 每天自动打卡的本地时间，`HH:MM`；留空则禁用 |

## 数据来源与已知边界

| 数据 | 来源 | 边界 |
|---|---|---|
| 每日时长 | `/readdata/detail` 的 `mode=monthly` + `baseTime` 逐月拉 | 年度模式不返回日级桶，所以历史要按 11 个月各拉一次（约 2.4 秒） |
| 每本书时长 | 各月 `readLongest` 取并集 | 只给 top10 且过滤 5 分钟以下，所以书架里如实标注「时长覆盖 N/M 本」 |
| `/book/getprogress` | 有 `recordReadingTime` 字段 | 实测 27 本全是 0，**不可用**，故未采用 |

## 注意事项

- `wr_skey` 有效期约 90 分钟，插件会在鉴权失效（-2012/-2013）时自动调
  `/web/login/renewal` 续期；整体登录态约 30 天，过期需重新粘贴 Cookie
- 不要在别的浏览器重新扫码登录，会使当前 Cookie 提前失效
- 计时以「当日阅读统计」为准，不是单本书的 `readingTime`
- 仅供学习研究，存在账号风险，请自行评估
